# Agent 通用协作规范

版本：1.4.0｜更新：2026-11-23｜状态：文档可使用及分享；当前会话采用与项目新会话自动采用需分别验证

面向各种场景的项目级协作：写作、研究、编程、数据分析、规划、学习、设计、办公和其他事务均可采用，示例不限定适用范围。“项目”可以是本地文件夹、产品内的项目，或当前对话中一组相关任务与资料。使用对话、普通文档以及 Agent 已有的能力，不要求安装插件、脚本或增强框架。

本规范只管理当前项目内的规则、资料、流程和知识。不规定用户级文件的名称与位置，不创建、修改或迁移用户级规则及产品内置个人记忆。产品已加载的有效上级规则仍正常适用。

项目知识只通过当前项目可审阅的资料维护和读取，可以是项目文档或已确认适用的原生项目知识载体。不主动将项目知识写入、导入或同步到产品内置记忆，不调整记忆开关、存储位置或管理方式。产品是否自行从对话中提取记忆，由其现有机制和设置决定；本规范不干预，也不承诺实现记忆隔离。

本规范覆盖需求对齐、规则与资料、计划执行、事项追踪、反馈纠偏、验证交付、知识与方法积累，以及长期续做。初次了解或向别人推荐，请先看 [项目介绍.md](项目介绍.md)：用普通语言说明背景、解决的问题、适用范围与使用方式。

## 推荐方式：通过 Skill 启用

支持 Agent Skills 的产品可以安装或导入 `agent-collaboration`（通用项目协作）。按所用产品实际提供的方式安装一次，再在每个需要采用的项目中选择或调用该 Skill，表达：

> 为当前项目启用通用协作规范，并继续已有任务。

Skill 自带同一套规范和空白模板。首次启用时，Agent 按 [技能接入](产品接入.md#技能接入) 将必要规范放到该项目的稳定位置，复用或建立最小项目入口；以后入口有效时直接提出普通任务。安装成功、当前调用成功和新会话自动采用分别核实，不能互相替代。

安装 Skill 本身不表示所有项目都已采用。已有项目版本和资料先复用；业务需求、台账与知识留在各自项目，不写回共享 Skill。只读、只评价或仅当前会话等明确限制优先。各产品的安装方式和可用性分别适配，不要求统一用户级路径，不修改用户级规则或内置记忆。

Skill 包额外包含 `SKILL.md`，它是短入口；下列 20 份规范正文与文档版同源。细则和模板仍按需读取。普通文档版不含 Skill 入口，按下面方式使用即可。

## 第一次使用

用户明确要求“按本规范协作”时，默认目标包括当前项目以后的新会话自动采用，首次最小项目接入属于本次请求的一部分。不再询问“要不要配置自动采用”，也不要求用户另回“接入”。首次接入的默认范围为创建一个最小项目入口，或在现有适用规则中增量加入、更新指向本规范的入口；保留其他规则及用户内容。采用 Skill 时，必要的项目内规范副本属于同次接入准备，不创建业务档案或覆盖已有规范。用户明确要求只读、只评价、暂不配置或仅当前会话时不写入入口，不追加接入选择题。产品权限与有效上级规则继续适用，不扩大到用户级配置、内置记忆、删除、发布或外发。

1. 有本地文件能力时，将完整文件夹放在当前项目中，并让 Agent 访问它。使用上传方式时，产品支持文件夹上传即可上传整包；支持压缩包读取时可上传 ZIP 并要求先解压读取。其他情况请自行解压后，先提供 [START.md](START.md) 和本次必要资料，用到流程或专题时再补充相应正文。
2. 把下面两句话发给 Agent，然后像平时一样交流。已经在讨论的任务可以直接继续，无需重新填写任务表格。

```text
请先阅读 START.md，按这套规范与我协作。

请根据当前对话中的需求选择必要的步骤和文档；缺少关键信息时问我，信息充分时按已有授权推进。
```

有本地文件能力时，也可以直接指明 `Agent通用协作规范/START.md` 的实际位置。这两句启动语启用当前会话，并默认要求 Agent 完成可执行的首次最小项目接入；实际自动生效仍须新会话验证。

### 首次采用时默认完成项目接入

1. **确定文件位置。** 选择一个该项目的新任务能持续访问、便于维护的位置。可以是本机项目目录或产品支持的项目资料位置；相对路径、目录同名或本次能读取，都不能单独证明以后可访问。不强制建立云端和本地两份规范。
2. **默认执行最小接入。** Agent 按 [产品接入.md](产品接入.md) 核对当前产品支持的项目规则文件。已有入口就复用，没有文件但有适用原生机制依据时，直接试建一个最小入口，不要求额外批准自动采用。保留用户内容；只读等明确限制优先。只有实际冲突、项目范围不明或产品权限阻塞时，报告对应问题，不把已经确定的目标重新交给用户选择。界面入口仅在实际存在时选用，不要求寻找固定菜单。
3. **在下一次正常使用中核实自动采用。** 同一项目的下一个新会话直接提出普通任务即可，不需要专门发送测试题，也不需要提醒读取规范或恢复上下文。Agent 根据可核对的读取记录或加载记录核实是否主动取得正文；没有实际证据时保留“待验证”。复述文件名或仅自报“已读”不能单独判定通过。维护者需要专门验收时，再使用验收记录中的测试步骤。
4. **正常使用。** 没有可用自动入口时，在每个新会话提供必要资料并使用上面的两句启动语，明确为手动采用；未核实的入口不宣称自动生效。对已验证的项目和运行方式，后续可正常交流，无需重复发送启动语。换产品、项目、设备或运行端，文件位置改变，或发现入口失效时，重新核实。跨端使用单独测试，不是本机使用的必需条件。

具体判定及记录方式见 [验收记录.md](验收记录.md)。配置成功与新会话验证成功分开记录。

## Agent 按需读取

Agent 先读取精简的 START 与本次必需项目资料，再根据触发条件选择流程的相关章节、事项追踪、产品接入或目标模板。已实际取得、仍在当前上下文中且有效的正文不重复读取。参考文档按需查阅，不把整包作为每轮必读资料；具体约定见 [按需读取资料](使用流程.md#按需读取资料)。首次接入单独处理一次，后续入口有效时不重复展开。

重要意图及时在现有需求和决定中保留依据，区分用户要求、已确认理解与 Agent 判断；可识别压缩、资料缺失或意图有疑问时再按 [上下文质量与意图核对](使用流程.md#上下文质量与意图核对) 补读和校正。无需新增固定文档或每次压缩前后的人工确认；记录与恢复仍需核实，不保证无损。

## 多事项项目怎样保持有序

有多个需要分别跟进、反复讨论或独立验收的事项，或事项需要跨阶段、跨窗口跟进时，由 Agent 按需启用 [事项追踪规则](事项追踪.md)。在已授权项目工作中默认整理必要记录，用户正常交流即可，无需额外要求建号或填写台账；简单任务不强制编号。

沿用项目原有编号、任务板或台账；缺少合适载体时，在已有状态记录中补最少信息。同一事项保留稳定编号、来源、当前状态、下一步与结案依据；具体字母和分类由项目约定，不要求每个问题单独建文件。多窗口更新需要协调写入，编号或处理者标记本身不提供并发保护。台账仍属于已有 9 类职责，不增加必建文件。

## 长项目默认怎样衔接

用户采用规范并授权实际工作后，Agent 负责在重要进展、阶段结束或可预见的暂停前留下可恢复的项目状态；同项目的新会话收到后续需求时，主动读取状态、相关决定与成果证据，再继续执行。用户不需要另外说“生成交接”或“恢复上下文”，也不需要手写交接材料。

先用足够完整、仍有效且下次能访问的原生记录或已有项目资料；只有缺口才在授权范围内补最少记录。必要的项目进度维护属于已授权工作的收尾，不另问是否交接；明确只读等限制优先。它不要求建立 9 个文件，也不表示可以读取不可见的旧聊天。自动采用规范和实际恢复进度分别核实；正常续做中可取得验证证据，无需用户额外安排测试。

## 使用约定

先复用当前实际可用、足以满足本次用途的原生项目功能或已有资料；只有存在信息缺口时才补记录或文档。同一范围、同一职责明确一个主要维护来源，其余只引用或按需导出快照，不要求两边持续手动同步。 这适用于全部 9 类职责，具体判断见 [选择承载方式](文档职责.md#选择承载方式)。原生功能是否足够，按内容、时效和后续可访问性核实，不仅凭产品介绍或功能名称判断。


- 9 类是项目内的信息职责，不要求每个项目建立 9 个文件。原生任务板、计划、交接、项目说明等已满足要求时，不另建同职责模板文件；简单任务可以全部在对话中完成。
- 用户正常表达需求即可；Agent 从当前对话和项目资料中整理必要信息，模板用于按需记录，不要求用户逐项填写。
- 优先使用已有文件和结构。新增、合并或移动项目文档应在用户授权范围内完成，不覆盖用户内容。
- 模板位于 `templates/`，保留空白供填写。模板、示例中的内容不代表当前项目事实，也不会仅因文件存在而自动生效。
- 共用的是规则、资料和方法。产品设置、内置记忆、工具、权限和执行环境仍由对应产品管理。
- `examples/` 供理解用法，`templates/` 供项目按需记录；二者都不要求每次读取。项目资料由使用者按本项目实际情况补充。

## 维护这套规范

维护者：当前使用者或其指定人员。正文与空白模板无运行时依赖；本版 Skill 仅使用 Markdown，不依赖脚本、API 或额外框架。具体文件操作仍由产品已有能力及权限提供。

维护仓库以 `Agent通用协作规范-v1.4.0/agent-collaboration/` 为单一内容来源，其中 `SKILL.md` 是 Skill 接入适配层，其余 20 份文档为共享正文。仓库内的 `tools/build_release.py` 生成 Skill 包与文档包，并用 `--check` 核对产物与来源逐文件一致；这只是维护工具，使用者不需要运行它。不要手工修改两个发行包中的副本来维护规则。

发生以下情况时更新：步骤反复被误解；出现重复文档或事实冲突；某产品的接入方式改变；用户发现需要新增的任务分支。每次更新同步版本、受影响引用和 [验收记录.md](验收记录.md)。新增细则优先归入对应专题；START 只保留核心约定和读取触发条件。调整入口时同步检查读取路径与长度，保留必要的授权、范围及验证边界。
